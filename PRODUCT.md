# Jarvis — описание продукта

> Функциональное описание системы для людей и для ИИ модуля «Улучшения».
> Поддерживается актуальным: любое изменение функциональности витрины или админки
> обновляет этот файл в том же коммите. Без паролей, ключей и персональных данных.

## Что это

Внутренняя система сервисного центра по ремонту техники (3 филиала: Каретная, Сегедская, Левитана).
Данные берутся из CRM Gincore (заказы на ремонт, кассы, ленты событий заказов) и Google Таблиц
(недельные отчёты мастеров), обрабатываются в **админке Jarvis** (работает на компьютере
администратора) и публикуются **снимками** на **витрину** (сайт для сотрудников).

Важно для понимания ограничений:
- Витрина показывает **снимок** на момент последнего обновления (обычно раз в день утром),
  а не живые данные. Дата снимка видна в шапке раздела.
- Витрина не может сама что-то менять в CRM. Действия сотрудников на витрине (решения по
  дебиторке, результаты прозвона, рейтинг Google, заявки «Улучшения») уходят в облачный
  «почтовый ящик» и подтягиваются админкой.
- Доступ к разделам выдаёт администратор по логину (матрица доступа по разделам/вкладкам).

## Витрина (для сотрудников)

Вход по логину/паролю. Главная — карточки разделов, к которым есть доступ.

### Качество
KPI ремонтов по квитанциям из CRM (рабочие заказы).
- **Общее** — таблицы по мастерам, раскрывающиеся; KPI мастера — среднее по его квитанциям.
- **По мастерам** — полосы среднего KPI (красный/оранжевый/зелёный), сводная таблица:
  KPI 0–100, сроки в днях, звонки клиенту, доработки.
- **Сводка / Динамика** — снимки по дням: число заказов, средний KPI, звонки, доработки, сроки.
- **Анализ** — операционный разбор на момент выгрузки: «срочные» квитанции (зависли,
  нет звонка, долго без диагностики и т. п.).
- KPI считается по сроку ремонта, наличию звонков клиенту после неудачных попыток, доработкам;
  квитанция в статусе «Готов»/«Выдан» в ремонте больше не считается.

### Процессы (вкладки)
- **Досогласования** — из недельных листов Google Таблицы: среднее и сумма досогласований,
  число квитанций, доля досогласованных, сумма «В отчёте», по неделям.
- **Дебиторка** — сверка недоплат: таблица отчётов мастеров против долгов в CRM.
  Флаги: красный — похоже на сокрытие долга; жёлтый — долг совпадает в отчёте и CRM;
  open — долг только в CRM; mismatch — суммы различаются. Динамика общей дебиторки CRM.
  Сотрудник с доступом может отметить решение по квитанции: «закрыть с разрешения руководства»,
  «оплата по факту была», «оплаты не было и не будет» — решение уходит администратору на модерацию.
- **КПД филиалов** — по месяцам и филиалам: приёмки (заказы), валовая прибыль и чистая
  прибыль по кассам, коэффициент возврата (отказы от ремонта / приёмки), графики сравнения.
- **Сбор отзывов** — менеджер сначала вводит текущий рейтинг Google и число отзывов по каждому
  филиалу (шаг 1), затем прозванивает очередь из 10 квитанций выданных клиентов (шаг 2) по
  скрипту и отмечает исход: оставит отзыв / недозвон / отказ / недоволен (с комментарием).
  Очередь пополняется из пула кандидатов.
- **Статистика по сбору отзывов** — исходы звонков, текущий рейтинг Google и его динамика
  (одна точка в день), обработка пула по дням и по менеджерам.
- **Качество буфера** — «буфер» = принятые квитанции без назначенного мастера.
  Показывает: сколько в буфере, сколько старше 3 дней, сколько роздано мастерам с прошлого
  снимка и **качество раздачи**: загрузка мастера (load index из числа открытых заказов,
  суммы дней в работе, доработок и заказов без диагностики) → зона high (>70) / ok (40–70) / low (<40).
  Отдать заказ мастеру в зоне low — хорошо, ok — норм, high — плохо; из этого оценка раздачи 0–100.
  Если день пропущен, сравнение идёт с последним снимком (до 7 дней) с пометкой «за N дн.».
  График «Раздача из буфера по дням»: по каждому дню снимка — кому из мастеров и сколько роздано, с оценкой уместности.

### КПД мастеров
Сравнение КПД и суммы работ мастеров по недельным отчётам из Google Drive.

### Финансы
Раздел в подготовке (пока пусто).

### Улучшения
Кнопка «Предложить улучшение» на всех страницах витрины. Сотрудник описывает пожелание,
замечание или ошибку; ИИ при необходимости уточняет (до 3 раундов) и оформляет заявку,
сотрудник проверяет и отправляет. Если похожая заявка уже есть — можно поддержать её «+1».
Во вкладке «Мои заявки» видны статусы: на рассмотрении / одобрено / в работе / готово /
отклонено и комментарий администратора.

## Админка Jarvis (только администратор)

- **Чат с ИИ** по данным CRM: суммы по статьям расходов и зарплатам, остатки касс, ремонты;
  сведение кассы по текстовому журналу смены (разбор операций, привязка запчастей к заказам).
- **Обновления** — запуск синхронизаций (Качество из CRM, Досогласования из таблицы, сверка
  дебиторки, КПД филиалов, пересчёт буфера), экспорт снимков на витрину, отправка анализа
  качества в Telegram.
- **Пользователи витрины** — логины, пароли, доступы к разделам.
- **Улучшения** — дорожная карта заявок сотрудников с оценкой ИИ; администратор одобряет,
  берёт в работу, отмечает готовность или отклоняет с комментарием (его видит автор).
- **Модули / ИИ** — подключения к Gincore, Google, настройки модели.

## Чего система не делает (частые недопонимания)
- Не показывает данные в реальном времени — только снимок последнего обновления.
- Не меняет данные в CRM с витрины.
